# Damage Reports — Minimal MVP

A working end-to-end system for managing damage reports: create reports, view
the list, view details, and change status. Backend is Node.js + Express with
in-memory storage; frontend is plain HTML/JS (no build step, no framework).

## Run it

```bash
npm install
npm start
```

Then open **http://localhost:3000** in your browser.

The server seeds two example reports on startup so the list isn't empty.
Storage is in-memory — restarting the server resets the data.

## Project structure

```
damage-reports/
├── server.js           # Express app: routes + in-memory store
├── package.json
└── public/
    ├── index.html       # App shell + styles
    └── app.js            # Hash-router SPA: List / Create / Details views
```

## Entity: DamageReport

| Field        | Type   | Notes                              |
|--------------|--------|-------------------------------------|
| id           | string | UUID, generated by the server       |
| reporterName | string | required                            |
| address      | string | required                            |
| damageType   | string | required, free text                 |
| description  | string | required                            |
| status       | string | `NEW` \| `IN_REVIEW`, defaults to `NEW` |
| createdAt    | string | ISO timestamp, set on creation      |

## API

| Method | Path                    | Description                          |
|--------|--------------------------|---------------------------------------|
| GET    | `/reports`               | List all reports (newest first)       |
| POST   | `/reports`               | Create a report (body: reporterName, address, damageType, description) |
| GET    | `/reports/:id`           | Get one report's details              |
| PATCH  | `/reports/:id/status`    | Update status (body: `{ "status": "NEW" \| "IN_REVIEW" }`) |

All endpoints return JSON. Validation errors return `400` with an `error`
message; unknown IDs return `404`.

### Example requests

```bash
# Create a report
curl -X POST http://localhost:3000/reports \
  -H "Content-Type: application/json" \
  -d '{"reporterName":"Dana Cohen","address":"12 Allenby St, Tel Aviv","damageType":"Water leak","description":"Ceiling leak in the kitchen."}'

# List reports
curl http://localhost:3000/reports

# Get one report
curl http://localhost:3000/reports/<id>

# Change status
curl -X PATCH http://localhost:3000/reports/<id>/status \
  -H "Content-Type: application/json" \
  -d '{"status":"IN_REVIEW"}'
```

## What's intentionally out of scope

Per the MVP brief: no authentication/roles, no file uploads, no styling
polish, no persistent database (in-memory only). These are straightforward
to add later — e.g. swap the in-memory array in `server.js` for a real DB
(SQLite/Postgres) behind the same four route handlers without touching the
frontend.
